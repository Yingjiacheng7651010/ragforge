# 07 · 实施路线图

> 把项目拆成 **7 个阶段 + 里程碑**，每个阶段有明确交付物和"完成标准"。
> 每完成一个里程碑就打一个 git tag，方便简历里写"分阶段交付"。
> 建议节奏：业余时间 6~8 周；全职 3~4 周。

---

## 总览

```
Phase 0 骨架与规范      → M0 空项目可 lint/type/test
Phase 1 数据入库管线    → M1 文档→chunk→向量/BM25 入库可查
Phase 2 检索能力        → M2 混合检索 + 重排跑通
Phase 3 生成与回答      → M3 端到端 RAG 问答（带引用）
Phase 4 评估体系        → M4 离线评测可量化指标
Phase 5 进阶能力        → M5 查询理解/Self-RAG/语义缓存
Phase 6 工程化收尾      → M6 可观测/CI/部署/压测
Phase 7 Agent + 简历    → M7 Agentic RAG + 文档交付
```

---

## Phase 0 · 骨架与规范（1~2 天）

**目标**：可复现、可协作的工程基座。

- [ ] `F01` 脚手架：`uv` + `pyproject.toml` + 目录 + `Makefile` + pre-commit + CI。
- [ ] `F02` 配置模块 + `.env.example`。
- [ ] 建立 `docs/` 文档骨架（即本套文档）。
- [ ] git init + 首次 commit + 保护 main 分支。

**完成标准（M0）**：`make lint && make type && make test` 全绿，CI 通过。

---

## Phase 1 · 数据入库管线（3~4 天）

**目标**：文档能进、能查。

- [ ] `F04` Embedding provider。
- [ ] `F05` 文档解析（PDF/MD/Word）。
- [ ] `F06` 分块策略（结构 + 父子分块）。
- [ ] `F07` 向量库/文档库（Milvus + ES）。
- [ ] 入库流水线 + Celery 异步任务 + 幂等。
- [ ] docker-compose 起 Milvus/ES/Redis。

**完成标准（M1）**：上传一份文档，能在 Milvus 用向量查到、在 ES 用 BM25 查到。

---

## Phase 2 · 检索能力（2~3 天）

- [ ] `F09` Dense/Sparse/Hybrid 检索 + RRF + 重排。
- [ ] 元数据过滤（doc_id、权限域）。
- [ ] 检索结果进 trace。

**完成标准（M2）**：同一查询，hybrid 检索返回融合重排后的 top-n，且比纯 dense 召回更全。

---

## Phase 3 · 生成与回答（3~4 天）

- [ ] `F03` LLM provider（fallback/流式/结构化）。
- [ ] `F11` 上下文装配 + 引用 + 生成。
- [ ] `F16` FastAPI 接口（chat + stream + upload）。
- [ ] `P1`/`P7` 提示词接入。

**完成标准（M3）**：curl `/v1/chat` 得到带 [1][2] 引用、可反查来源的答案；SSE 流式可用。

---

## Phase 4 · 评估体系（3~4 天）★ 关键里程碑

- [ ] 构建黄金集（人工 50~100 条 + 合成扩充）。
- [ ] `F13` 检索指标 + RAGAS 生成指标 + 报告 CLI。
- [ ] 跑出**第一份基线报告**，记录 recall@5 / faithfulness 等数值。
- [ ] 固化典型样例为 e2e 回归。

**完成标准（M4）**：`python -m ragforge.eval run` 输出完整指标报告，可作为后续改动的对比基线。

> ⭐ 从这一阶段起，你才真正进入"字节式 RAG"：每个改动都有数据支撑。

---

## Phase 5 · 进阶能力（4~5 天）

- [ ] `F08` 查询理解（意图/改写/多查询/HyDE）。
- [ ] `F10` Self-RAG / CRAG。
- [ ] `F12` 语义缓存。
- [ ] 每加一项 → 跑评测对比，记录提升。

**完成标准（M5）**：开启查询理解 + 重排 + 语义缓存后，recall/faithfulness/延迟/成本相对 Phase 4 基线有**可量化**提升。

---

## Phase 6 · 工程化收尾（3~4 天）

- [ ] `F14` 可观测性（trace/metric/log）+ Grafana 面板。
- [ ] `F15` 护栏。
- [ ] `F18` 补测试到覆盖率 ≥85%。
- [ ] Docker 镜像 + k8s 清单（或 docker-compose 完整部署）。
- [ ] 压测：Locust 打 `/v1/chat`，产出 P50/P95/P99。

**完成标准（M6）**：一次 query 全链路可观测；压测报告有分位延迟；CI/CD 全绿。

---

## Phase 7 · Agent + 简历（3~4 天）

- [ ] `F17` Agentic RAG（Planner/Executor/Reflector）。
- [ ] 多跳样例跑通并评测。
- [ ] 整理简历 bullet（用 `08-简历包装与面试准备.md`）。
- [ ] 写项目 README（架构图、亮点、指标截图）。
- [ ] 录一个 3 分钟 demo（加分项）。

**完成标准（M7）**：仓库完整可运行，README 有架构图 + 指标 + demo；简历可写。

## 风险与对策

| 风险 | 对策 |
| --- | --- |
| 模型 API 费用高 | 评估用小模型；日常用 DeepSeek/本地模型；设成本预算 |
| Milvus/ES 环境难搭 | 用 docker-compose 一键起；本地 dev 可用 Qdrant 简化 |
| 黄金集人工标注慢 | 先用合成数据跑通流程，人工核心集逐步补充 |
| 分块/参数调优耗时 | 用网格搜索脚本自动化，一次跑多组 |
| 沉迷调 prompt 忽略工程 | 记住：先保证指标可测，再谈优化 |
