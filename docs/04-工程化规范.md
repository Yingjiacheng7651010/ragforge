# 04 · 工程化规范

> 本文档定义代码层面的**硬性规范**。这是"看起来像大厂工程师写的代码"和"看起来像学生作业"的区别。
> 核心信条：**类型安全、依赖注入、可测可测、CI 兜底、全程可观测**。

---

## 1. 代码质量三件套（lint / format / type）

| 工具 | 用途 | 关键配置 |
| --- | --- | --- |
| `ruff` | 格式 + lint | `line-length=100`，规则集 `E,F,I,UP,B,SIM` |
| `mypy` | 类型检查 | **strict 模式**，禁止 `Any` 逃逸 |
| `pre-commit` | 提交前强制 | ruff + mypy + 单测快照 |

```toml
# pyproject.toml 摘要
[tool.mypy]
strict = true
disallow_untyped_defs = true

[tool.ruff]
line-length = 100
select = ["E", "F", "I", "UP", "B", "SIM"]
```

**强制规则**：
1. 所有公共函数/方法必须有**完整类型注解**与**参数类型**。
2. 禁止裸 `except:`，禁止 `# type: ignore` 无理由。
3. 用 `dataclass`/`pydantic` 定义数据结构，不用裸 dict 传值（对外边界除外）。
4. 常量集中定义，魔法数字命名化。

## 2. 依赖注入（DI）

不搞复杂的框架，用**轻量容器 + 工厂函数**，核心是"可替换、可测试"。

```python
# container.py
class Container:
    def __init__(self, settings: Settings):
        self.settings = settings
        self._llm: BaseLLM | None = None

    @property
    def llm(self) -> BaseLLM:
        if self._llm is None:
            self._llm = build_llm(self.settings)  # 按配置装配具体 provider
        return self._llm
```

**规则**：
- 模块之间**只依赖抽象（Protocol/ABC）**，不 `import` 具体实现。
- 所有外部依赖（LLM、向量库、缓存）通过 `container` 获取。
- 测试时注入 `FakeLLM` / `FakeVectorStore`，无需真实服务。

## 3. 统一异常与错误码

```python
class RAGForgeError(Exception):
    def __init__(self, code: str, message: str, http_status: int = 500): ...


# 常见错误码

# E_CONFIG           配置错误
```

**规则**：业务代码只抛 `RAGForgeError` 子类；API 层统一捕获 → 转标准响应（含 `code`、`trace_id`）。

## 4. 日志规范（structlog + JSON）

```python
import structlog

logger = structlog.get_logger()

logger.info("retrieve_done", query=q, top_k=k, latency_ms=123, trace_id=..., request_id=...)
```

**规则**：
1. 日志一律 **JSON 结构化**，字段用 key=value，禁止字符串拼接。
2. 每个请求生成 `request_id`，每个 span 生成 `trace_id`，全链路透传。
3. **敏感信息脱敏**：API key、用户明文一律 `***`。
4. 日志分级：`debug`（内部细节）/`info`（关键节点）/`warning`（降级、重试）/`error`（需告警）。

## 5. 可观测性规范

| 信号 | 工具 | 必采内容 |
| --- | --- | --- |
| Trace | OpenTelemetry + Langfuse | query 全链路 span、每步耗时/token/分数 |
| Metric | Prometheus | 延迟分位、QPS、错误率、缓存命中率、成本 |
| Log | structlog → Loki | 结构化日志，关联 trace_id |

**Trace span 命名约定**：`rag.query` / `rag.rewrite` / `rag.retrieve.dense` / `rag.retrieve.sparse` / `rag.rerank` / `rag.self_rag` / `rag.generate`。

## 6. 测试规范

```
tests/
├── unit/            # 单模块，全部 Fake 依赖
├── integration/     # 真实 Milvus/ES/Redis（docker-compose 起）
└── e2e/             # 端到端：上传文档 → 问答 → 断言引用存在
```

**规则**：
1. **覆盖率 ≥ 85%**（核心模块：检索、生成、分块、缓存必须 ≥ 90%）。
2. **Mock LLM**：单测绝不真调 LLM，用 `FakeLLM` 返回固定响应，测的是"你的逻辑"不是"模型的输出"。
3. **黄金用例回归**：评测集里的典型样例固化为 e2e 断言，防回归。
4. **快照测试**：prompt 渲染结果做快照，防止无意改动提示词。

```python
# 单测示例：测试 RRF 融合逻辑
def test_rrf_fusion_ranks_consensus_first():
    hits_a = [Hit("a", 1), Hit("b", 2)]
    hits_b = [Hit("b", 1), Hit("c", 2)]
    fused = rrf_fuse([hits_a, hits_b], k=60)
    assert fused[0].chunk_id == "b"  # 两路都靠前 → 融合后第一
```

## 7. CI/CD 流水线（GitHub Actions）

```yaml
# .github/workflows/ci.yml 摘要
jobs:
  lint:   ruff check + ruff format --check
  type:   mypy --strict
  test:   pytest --cov，覆盖率门槛 85%，不达标失败
  build:  构建 docker 镜像，打 tag
  deploy: 手动/自动触发，k8s 灰度(Canary) → 观察指标 → 全量
```

**规则**：
- 任何一个 job 失败 → 阻断合并（PR 不可合入）。
- 覆盖率下降 → CI 直接红，不允许"以后补测试"。
- 主分支受保护，所有改动走 PR + review。

## 8. 12-Factor 与配置管理

| Factor | 落地 |
| --- | --- |
| 配置与代码分离 | 全部走环境变量，`.env` 不入库 |
| 依赖显式 | `uv.lock` 锁定，可复现 |
| 进程无状态 | 状态全在 Redis/向量库，API 可水平扩容 |
| 日志即流 | stdout JSON，容器采集 |
| 一次构建多次部署 | 同一镜像，仅环境变量不同 |

---

## 9. 目录与命名规范

- 包名 `ragforge`，`src/` 布局（避免隐式 import 污染）。
- 模块内：`base.py`（抽象）、`service.py`（业务）、`schemas.py`（数据结构）、`exceptions.py`（异常）。
- 命名：函数/变量 `snake_case`，类 `PascalCase`，常量 `UPPER_CASE`。
- 每个模块必须有 `__init__.py` 导出公共 API（`__all__`），隐藏内部实现。

---

## 10. 文档规范

- 每个模块一个 `README.md` 或 docstring 说明：职责、输入输出、示例。
- 关键算法（RRF、语义缓存、父子分块）写清**原理 + 复杂度 + 为什么这么选**。
- 架构变更同步更新 `01/02` 文档，禁止文档与代码脱节。
